# V18: tabs, camera, audio, early-game balance

All code is in `index.html`, in the block headed `V18`.

## UIManager: mutually exclusive tabs

- `UIManager.PANELS` maps each nav key to its panel element and renderer. Every nav entry in `UIManager.MAIN` is exclusive with every other.
- `togglePanel(k)`:
  1. clears the context popup
  2. if `k` is a panel, closes it when it's already open; otherwise it closes every other panel, the menu and the blueprint tool, then opens it and plays `ui_open`
  3. if `k` is a view or tool (Factory, World, Blueprint, Overlay, Menu), closes the panels first, then switches the view or starts the tool
- Every other entry point also goes through the manager:
  - the keys `E`, `C`, `P`, `T`, `K`, `G` and `M`
  - `toggleInv`, `toggleCo`, `toggleStats` and `toggleModal`
  - `openCo` from alerts
  - `openMenu`
- `activeKey()` returns the single highlighted key: the open panel, else the menu, else the blueprint tool, else the current view. The nav renders it with `class="active"`, `aria-pressed` and a stable `id="nav-<key>"`. The overlay keeps its own `on` state.
- `initUIBindings()` runs once in `start()`. It puts one delegated listener on `#nav`:
  - `pointerdown` clears popups.
  - `click` calls `navAct` and stops propagation, so the document handler never toggles a second time.
- **Escape order:** full-screen overlays (help, menu, win, stage card), then the open tab (`UIManager.escape`), then the blueprint tool, then the world province panel, then the entity panel, then the held tool.
- **President fix:** the President panel used to stack under other panels, and Escape ignored it. It is now exclusive, Escape closes it, and its header has a Character Editor button.
- **Layout fix:** centred panels stay above the nav bar. `--navh` is measured each HUD update and sets `top` and `max-height`. Before this, Research covered the nav bar on short screens and blocked every tab button.

## Free look (right-drag)

```
right button down → FreeLook.down (remember cursor, camera, tile)
move > 5 px       → detach: camFollow off, cursor "grabbing", camera = start − drag / zoom
release, no drag  → right-click behaviour: remove the building under the cursor
release after drag, factory view → per setting:
   glide (default): FreeLook.snap; each frame cam += (President − cam) × (1 − 0.84^(dt × 60)) until < 1.5 px
   snap: camera jumps to the President
   stay: camera remains where you left it
```

- While dragging, following the President is suspended even if you walk with WASD.
- The arrow keys cancel a glide.
- Right-drag also pans the world map, where there is no President to return to.

## Audio

`sfx()` still synthesizes every sound with WebAudio, so no files are needed. Everything now goes through one compressor so overlapping sounds don't clip.

| Key | Sound |
| --- | --- |
| `coin` | cash register: drawer clack, a two-note bell (G6, C7 with bell overtones) and a coin shimmer. At most one every 0.9 s |
| `ui_open` / `ui_close` | short rising or falling clicks |
| `place` | filtered thud with a low triangle tone |
| `remove` | noise crunch with a falling square tone |
| `error` | two-step low buzz, for failed placements (wrong land, river, coast, ore, no items). Not for "busy" tiles while dragging |

## Balance and drill targeting

- **Starting veins:** `HOME_ORE = 4` multiplies the ore per tile of every deposit in the starting province (about 2,000 per tile, against about 670 elsewhere). The random number sequence is unchanged, so deposit shapes stay the same.
  - Existing saves keep the amounts of tiles already mined. Unmined home tiles get the new amounts.
- **Advanced Drill Targeting** (`drill_targeting`, Industry tier 1, $1,200 + 40 iron plates + 20 gears, needs Automation):
  - When a drill's current tile runs dry, `retarget(e)` scans the 3×3 around the drill for the same ore it last mined.
  - It skips tiles you don't own, tiles under another drill and tiles another drill is already targeting, then picks the richest.
  - The target is stored as `e.mt` (saved with the game).
  - `updDrill`, the drill panel and `drawDrillTargets` all read `drillTile(e)`. A dashed green line and box show the target.
